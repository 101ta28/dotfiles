# 日本語技術文書の文章規範

読者が順に読んで、対象、主張、根拠、適用条件を理解できる文章にする。依頼された修正範囲と既存の文体を尊重する。

## 構成と論証

- 冒頭で読者の問題と主旨を示す。段落は一つの話題を扱い、前後の論理関係が分かる順に並べる。接続詞や段落構成を一律の型に固定しない。
- 概念は何の種類のものかを示してから性質を説明し、定義・訳語・対象範囲を文書全体で揃える。
- 例を追加するときは、何を説明し、前の例とどう異なるかを明らかにする。図・表・コードが別の例なら、一方で確認した性質を他方に当てはめない。
- 因果関係は仕組みと条件を伴って述べる。複数の原因や別々の決定を一括りにせず、例が支える範囲に主張を限定する。
- 推測、可能性、反実仮想、作中人物の認識を、推敲によって事実の断定へ変えない。確認していないことを確認済みと書かない。
- 対比が必要なら両側を同じ基準で説明し、退ける解釈とその根拠を特定する。反論や限定を処理したうえで議論を進める。
- 前方参照や途中で立てた問いは、約束した箇所で扱う。未解決の論点はその状態を明記する。

## 表現と情報量

- 冗長さは文字数でなく、同じ主張の重複で判断する。動機、対象、操作、因果、条件が順読みで分かる長さと反復は残す。
- 具体例に必要な数値・識別子は残し、後で使わない固有名詞や装飾的な精度は省く。指示語の参照先を一意にする。
- 日本語として自然な述語で、主体や処理と観察できる結果を書く。「データが語る」は「データから分かる」、「開かれた問い」は「未解決の問い」とする。「効く」は効果と条件を具体的に書く。
- 対象を曖昧な「AI」「ツール」でまとめず、導入済みの用語を使う。人物名は原綴りを基本とし、人名を冠した概念などの定着した日本語名は尊重する。
- 中身のない強調、進行予告、同じ結論の言い換え、姿勢だけを示す表現を省く。語句の一律禁止にせず、その文が新しい情報を加えるかで判断する。
- 文体に合う自然な文末を選ぶ。二人称の呼びかけ、修辞疑問、太字、短い決め台詞は必要な箇所に絞り、架空の人物や感情を説明の飾りとして足さない。
- 見出しは扱う対象や読者の問いを特定するものにする。結びでは議論の実用上の帰結を示し、本文全体を繰り返さない。

納品前に変更箇所とその前後を読み、参照切れ、論理の飛躍、不確実性の欠落を確認する。章全体を組み替えた場合は、章を通して確認する。
