# 説明文の緩急

内容と論理を保ちながら、読者が具体的な事実を観察し、意味を考え、判断を確かめられる流れを作る。修正範囲と既存の文体を優先し、手順書や短い回答へ読み物の演出を持ち込まない。

## 読み進めにくさの診断

対象箇所を前後と続けて読み、読み返しが必要になる場所と、新しい情報が進まない場所を特定する。文の長さや同じ語尾の回数だけで修正を決めない。

| 症状 | 調整する点 |
|---|---|
| 条件や括弧が重なり、何を述べる文か見失う | 主述を近づけ、独立した説明を別文へ移す。条件と、その条件がかかる主張は近くに置く。 |
| 短文が続き、事実同士の関係を読み手が補う必要がある | 関連する文をつなぎ、根拠のある因果・順序・対比を示す。 |
| 抽象的な評価や同じ結論が繰り返される | 重複を減らし、資料にある事例・操作・観察結果を主張の近くに置く。 |
| 文末や箇条書きの型が続き、論の進展が分からない | 各文の役割とつながりを見直す。並列項目は残し、説明の連鎖は段落にする。 |

## 編集の判断基準

- 具体的な記録・数値・コードと、その意味や限界を説明する段落を組み合わせる。短文と長文、断定と留保の配置は内容に合わせ、文数や交互配置を固定しない。
- 同じ文末が続いても自然に読めれば保つ。変化をつけるためだけに体言止めや修辞疑問を足したり、断定と推測を入れ替えたりしない。既存の敬体・常体を保つ。
- 読点は係り受けや読み違いを確かめて調整する。短く切りすぎた文や名詞止めは、前後とつないで関係を明示する。文長、読点数、漢字率を一律に揃えない。
- 続きを読む理由は、対象にある疑問、期待とのずれ、判断の難しさから作る。演出のために事実、感情、思い込み、未解決の問いを捏造しない。
- 冒頭は読者の問題と主旨が伝わる形にする。必要な結論を引き延ばしたり、常に問いを未解決にしておいたりする必要はない。
- 理論から例へ進むか、具体的な疑問から理論を導入するかは、読者の知識と説明の目的で選ぶ。例や列挙が議論にどう関係するかを示す。
- 「次は何を書くか」「この章がどう見えるか」しか伝えない文は省く。範囲の説明、必要な道案内、具体的な反論処理は残してよい。
- 緩急をつけるための文も、対象についての情報や根拠のある判断を加えるものにする。「先に答えを半分だけ置く」のような執筆操作の宣言で代用しない。
- 結びは既出の具体例や読者の実務につなげる。本文で答えると約束した問いを放置せず、残る不確実性は明示する。

## 判断例

次は本スキル用に作成した例。文をつなぐ場合も、測定値と解釈の範囲を保つ。

修正前:

> 同じ入力で試しました。キャッシュなしでは800 msでした。キャッシュありでは200 msでした。計測はそれぞれ1回でした。毎回同じ差が出るかは不明です。

修正後:

> 同じ入力で試すと、キャッシュなしでは800 ms、ありでは200 msでした。ただし、計測はそれぞれ1回で、毎回同じ差が出るかは不明です。

測定条件と結果を一文にまとめ、次の文で解釈の限界を示した。「処理が常に4倍速くなる」という一般化や、値だけでは分からない高速化の仕組みは加えない。

## 推敲の確認

変更箇所を前後と続けて読み、必要な文脈、条件、不確実性が残っているか確認する。文の分割・結合で否定や留保のかかる範囲が変わっていないかも確かめる。追加した短文が既出の主張の繰り返しや進行実況になっていれば、削るか対象の説明に直す。

語句や形式の出現数は見直す箇所を探す手掛かりにとどめる。読みやすさは、対象と論理を追えて、次の文が理解を進めるかで判断する。形式だけでAI生成かどうかを断定しない。

技術的な論証や日本語表現も修正する場合は、[japanese-tech-writing](../japanese-tech-writing/SKILL.md) を参照する。緩急だけの修正で全文の規範点検を追加する必要はない。
